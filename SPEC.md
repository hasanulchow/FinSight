## 1. Overview

### 1.1 Problem
Before a client conversation, advisors at a wealth management firm need to get up to speed on a stock fast. Today that means checking a quote terminal, pulling financials and reading long SEC filings (10-K, 10-Q, 8-K), which takes 30–60 minutes per company.

### 1.2 Solution
A mobile app where an advisor enters a ticker and, in about a minute, receives a structured briefing produced by a team of AI agents. The briefing combines:
- the current quote and key statistics
- multi-year financials taken directly from SEC XBRL data
- summaries of the latest 10-K (business, management discussion, risk factors)
- recent filing activity
- neutral, compliance-reviewed talking points

Every briefing is automatically quality-scored, so advisors and the firm can see how far to trust it.

### 1.3 Users
| User | Need |
|---|---|
| **Financial advisor** (primary) | A fast, reliable, citation-backed summary of a stock before a client meeting |
| **Compliance / firm admin** (secondary) | Assurance that AI output contains no investment recommendations, and a record of quality scores and advisor feedback |

### 1.4 Goals
1. Get an advisor up to speed on any SEC-registered US stock in under 2 minutes of reading.
2. Ground every statement in source data: SEC filings and market data.
3. Never produce buy/sell/hold recommendations, price predictions or guarantees.
4. Measure output quality on every briefing (LLM evaluation).

### 1.5 Non-goals (v1)
- Personalized advice or portfolio fit for specific clients
- Non-US or non-SEC securities, ETFs, mutual funds, crypto
- Real-time streaming quotes or charting
- Earnings call transcripts, news feeds, analyst ratings
- Free-form chat over filings

## 2. User Experience

### 2.1 Screens
| Screen | Contents |
|---|---|
| **Login** | Email + password sign-in and sign-up (Supabase Auth). Shows a confirmation notice if email verification is on. |
| **Home** | Ticker input with a "Brief me" button; list of the user's recent briefings (ticker, company, date, overall quality score, or running/failed state); pull to refresh; sign out. |
| **Briefing: in progress** | Spinner, the current pipeline step (e.g. "Analysts at work: market, fundamentals, filings, risks"), and the list of agents. Updates every 2.5 s. |
| **Briefing: complete** | See 2.2. |
| **Briefing: failed** | The error message (e.g. unknown ticker). |

### 2.2 Briefing content (in display order)
1. **Snapshot:** ticker, company name, industry, price, day change ($ and %), market cap, P/E (TTM), 52-week range, beta, quote timestamp
2. **Executive summary:** 4–6 sentences
3. **Key takeaways:** 4–6 bullets
4. **Market:** commentary and 3–5 notable stats
5. **Financials (SEC filings):** table of revenue, operating income, net income, diluted EPS, cash and long-term debt for up to 4 years; summary; trend per metric (▲ ▼ ▬ ◆); strengths; concerns
6. **Business:** overview, segments, management outlook
7. **Top risks (10-K Item 1A):** 5 risks, each with a category, plain-language summary and a verbatim evidence quote from the filing
8. **Recent filings:** up to 6 notable 10-K/10-Q/8-K filings with summaries, and a link to the latest 10-K on SEC.gov
9. **Client talking points:** 3–5 neutral points
10. **Questions to consider:** 2–4 open questions
11. **AI quality evaluation:**
    - overall score and four score bars
    - the judge's rationale
    - possibly unsupported claims
    - automated checks passed
    - number of compliance edits
    - expandable agent trace (agent, latency, tokens)
12. **Feedback:** 👍 / 👎
13. **Disclaimer**

### 2.3 Primary flow
1. The advisor signs in.
2. They enter a ticker and tap "Brief me".
3. The API creates a briefing record and returns its id immediately (HTTP 202).
4. The app opens the briefing screen and polls for status.
5. The agent pipeline runs in the background, updating the progress text.
6. When the status becomes `complete`, the full briefing is shown. The advisor reads it, opens the 10-K if needed, and leaves feedback.
7. The briefing stays in the advisor's history.

## 5. Multi-Agent Pipeline

### 5.1 Orchestration
```
1. Look up company           ticker → CIK, name (SEC)
2. Gather data (parallel)    quote (Finnhub) · filing list · XBRL financials (SEC)
3. Read latest 10-K          extract Item 1, Item 1A, Item 7
4. Specialists (parallel)    Market · Fundamentals · Filings · Risk
5. Synthesis                 Briefing Writer
6. Compliance                Compliance Reviewer
7. Evaluation                deterministic checks + Evaluator (LLM judge)
8. Persist                   briefing content, evaluation; status → complete
```
Any failure in steps 1–7 marks the briefing `failed` with the error message. If 10-K extraction fails, the pipeline continues and agents receive "Not available".

### 5.2 Agent runner (`lib/llm.js`)
Every agent is one Claude Messages API call with:
- a system prompt (shared house rules plus the agent's role)
- one user message containing the data
- `output_config.format` = a strict JSON schema (all fields required, no extra properties)
- `output_config.effort` = per-agent effort level
- `max_tokens` = 16,000
- server-side fallback beta `server-side-fallback-2026-07-01` with `fallbacks: "default"`

A `refusal` or `max_tokens` stop reason is treated as an error. Each call writes one `agent_logs` row, on success or error.

**House rules (shared by all analyst agents):**
- use only the provided data, and never invent numbers, dates or facts
- stay neutral, with no buy/sell/hold recommendations and no price predictions
- be concise and plain-language for an advisor audience

### 5.3 Agent catalogue
| # | Agent | Effort | Input | Output schema (fields) |
|---|---|---|---|---|
| 1 | **Market Analyst** | low | Quote + key stats JSON | `headline`, `commentary`, `key_stats[]` |
| 2 | **Fundamentals Analyst** | medium | XBRL annual series JSON | `summary`, `trends[{metric, direction: up\|down\|flat\|mixed, detail}]`, `strengths[]`, `concerns[]` |
| 3 | **Filings Analyst** | medium | Recent filings list, 10-K Item 1 (≤30k chars), Item 7 (≤80k chars) | `business_overview`, `segments[]`, `management_outlook`, `recent_events[{date, form, summary}]` |
| 4 | **Risk Analyst** | medium | 10-K Item 1A (≤120k chars) | `overview`, `top_risks[{title, category, summary, evidence}]` (5 risks; category ∈ market, operational, financial, regulatory, legal, competitive, macroeconomic, technology, other) |
| 5 | **Briefing Writer** | medium | Outputs of agents 1–4 | `executive_summary`, `key_takeaways[]`, `talking_points[]`, `questions_to_consider[]` |
| 6 | **Compliance Reviewer** | low | Writer output | `revised` (same schema as Writer), `issues_found[{original, reason, fix}]` |
| 7 | **Evaluator** | medium | Final briefing + raw source data (quote, financials, filings, 10-K sections) | `faithfulness`, `completeness`, `compliance`, `clarity` (1–5), `rationale`, `unsupported_claims[]` |

When a section is cut to its character limit, the agent is told the shown and total lengths.

### 5.4 Compliance rules (agent 6)
Rewrite any text that:
- recommends buy/sell/hold or calls the stock a good/bad investment
- predicts or targets prices or returns
- promises or guarantees performance
- reads as personalized advice
- uses promotional or exaggerated language

Facts and figures stay unchanged.

**Disclaimer (fixed text):**
> For internal advisor use only. This summary is generated by AI from public market data and SEC filings, may contain errors, and is not investment advice or a recommendation to buy, sell or hold any security. Verify against the original filings before use with clients.

## 6. Data Sources and Tools

### 6.1 SEC EDGAR (`tools/sec.js`)
All requests send the `SEC_USER_AGENT` header, as SEC requires.

| Function | Endpoint | Behavior |
|---|---|---|
| `lookupCompany(ticker)` | `www.sec.gov/files/company_tickers.json` | Ticker → `{ticker, name, cik}` (CIK zero-padded to 10 digits). Cached in memory for the life of the process. |
| `getRecentFilings(cik)` | `data.sec.gov/submissions/CIK##########.json` | The 12 most recent 10-K/10-Q/8-K filings (form, dates, 8-K item codes, document URL), plus `latest10K` found separately in the full recent list. |
| `getFinancials(cik)` | `data.sec.gov/api/xbrl/companyfacts/CIK##########.json` | The last 4 calendar years for each metric (below). When a company has switched XBRL tags over time, the tag with the most recent data wins. |
| `get10KSections(url)` | 10-K primary document | HTML → text, then extracts Item 1 (Business), Item 1A (Risk Factors) and Item 7 (MD&A). Start and end markers must be full headings (item number + title) and tolerate split drop-cap letters. The longest start→end span is used, which skips the table of contents. Sections under 500 chars are treated as missing. |

**XBRL metrics:**
| Metric | Type | Tags (in priority order) |
|---|---|---|
| revenue | annual (`CY####` frames) | Revenues, RevenueFromContractWithCustomerExcludingAssessedTax, RevenueFromContractWithCustomerIncludingAssessedTax, SalesRevenueNet |
| operatingIncome | annual | OperatingIncomeLoss |
| netIncome | annual | NetIncomeLoss |
| epsDiluted | annual | EarningsPerShareDiluted, EarningsPerShareBasicAndDiluted |
| operatingCashFlow | annual | NetCashProvidedByUsedInOperatingActivities |
| cash | year-end (`CY####Q4I` frames) | CashAndCashEquivalentsAtCarryingValue |
| totalAssets | year-end | Assets |
| totalLiabilities | year-end | Liabilities |
| longTermDebt | year-end | LongTermDebtNoncurrent, LongTermDebt |
| stockholdersEquity | year-end | StockholdersEquity |

### 6.2 Finnhub (`tools/quote.js`)
`/quote`, `/stock/metric?metric=all` and `/stock/profile2`, called in parallel. They return:
- price, change, change %, open, high, low, previous close, `asOf`
- 52-week high and low, P/E, beta, dividend yield
- market cap (USD millions), industry, exchange, logo

The request fails if no price is returned.

## 7. API Specification

Base URL: Vercel deployment URL (local: `http://localhost:3001`). All routes except `/health` require `Authorization: Bearer <Supabase access token>`, verified with `supabase.auth.getUser`.

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/health` | – | `200 {ok: true}` |
| POST | `/briefings` | `{ticker}` | `202 {id}`. `400` invalid ticker, `401` unauthenticated |
| GET | `/briefings` | – | `200 [{id, ticker, company_name, status, created_at, evaluations:[{overall}]}]`, newest first, max 50 |
| GET | `/briefings/:id` | – | `200 {id, ticker, company_name, status, progress, content, error, created_at, evaluations:[…], agent_logs:[{agent, model, input_tokens, output_tokens, latency_ms, status}]}`. `404` if not found or not owned |
| POST | `/briefings/:id/feedback` | `{rating: 1\|-1, comment?}` | `200 {ok: true}`. `400` bad rating, `404` not owned |

**Briefing `status`:** `running` → `complete` or `failed`.

**`content` shape:**
```
company       {ticker, name, cik, industry, exchange, logo}
snapshot      Finnhub quote object (§6.2)
financials    XBRL series {metric: [{year, value}]}
executive_summary, key_takeaways[], talking_points[], questions_to_consider[]
market        Market Analyst output
fundamentals  Fundamentals Analyst output
business      Filings Analyst output
risks         Risk Analyst output
sources       {latest10K, filings[]}
compliance    {issues_found[]}
disclaimer    string
```

## 8. Data Model (Supabase)

| Table | Key columns | Notes |
|---|---|---|
| `briefings` | `id`, `user_id → auth.users`, `ticker`, `company_name`, `status` (running/complete/failed), `progress`, `source_data` jsonb, `content` jsonb, `error`, `created_at`, `completed_at` | Index on `(user_id, created_at desc)` |
| `evaluations` | `id`, `briefing_id`, `faithfulness`, `completeness`, `compliance`, `clarity` (1–5), `overall` numeric(3,2), `rationale`, `issues` jsonb, `checks` jsonb, `judge_model` | One per briefing |
| `agent_logs` | `id`, `briefing_id`, `agent`, `model`, `input_tokens`, `output_tokens`, `latency_ms`, `status`, `error` | One per LLM call |
| `feedback` | `id`, `briefing_id`, `user_id`, `rating` (−1/1), `comment` | Unique `(briefing_id, user_id)` |

**Access control:**
- Row-level security is enabled on all four tables.
- Users can `select` their own rows. For `evaluations` and `agent_logs`, that means rows whose briefing they own.
- All writes go through the API using the service-role key, which never ships in the app.

## 9. LLM Evaluation

### 9.1 Deterministic checks (every briefing, no LLM cost)
| Check | Pass condition |
|---|---|
| `has_disclaimer` | Disclaimer present |
| `no_banned_phrases` | None of these patterns match: "you should buy/sell/hold", "buy/sell rating/recommendation", "guarantee(d/s)", "risk-free", "price target", "will rise/soar/double/go up" |
| `has_quote` | Snapshot price present |
| `quote_fresh` | Quote timestamp within 4 days |
| `has_financials` | At least one XBRL series is non-empty |
| `has_risks` | At least one risk returned |
| `has_summary` | Executive summary present |

The result is stored as `checks` with `passed`/`total` and any banned-pattern hits.

### 9.2 LLM-as-judge (every briefing)
The Evaluator agent (model `EVAL_MODEL`) compares the final briefing with the raw source data and scores:
| Dimension | Definition |
|---|---|
| Faithfulness | Every claim is supported by source data; no invented facts or numbers |
| Completeness | Covers price, business, financials, outlook, risks and recent filings |
| Compliance | No recommendations, predictions, guarantees or personalized advice |
| Clarity | An advisor can get up to speed in under two minutes |

Scores are clamped to integers from 1 to 5. `overall` is the mean of the four, to 2 decimal places. The judge also lists any unsupported claims.

### 9.3 Offline evaluation (`npm run eval`)
- **Golden set:** AAPL, MSFT, JPM, CVX, PFE, each with expected risk keywords.
- **Per ticker:** the four judge scores, overall, checks passed, **risk recall** (share of expected keywords found in the risk output) and runtime.
- **Output:** a console table, averages, and a JSON file in `server/evals/results/`.
- **Arguments:** tickers can be passed to run a subset or new tickers.

### 9.4 Observability and feedback
- `agent_logs` gives a per-agent token and latency trace for every briefing; the app shows it.
- `feedback` records advisor ratings, for comparison with judge scores.

## 10. Non-Functional Requirements

| Area | Requirement |
|---|---|
| **Latency** | Briefing request returns < 1 s; full briefing typically 30–90 s (target < 120 s). |
| **Cost** | 7 LLM calls per briefing (Sonnet 5.5). Largest inputs are the 10-K sections, capped at 230k chars total. |
| **Reliability** | The SDK retries transient API errors (2 retries by default). Server-side model fallback on refusals. A failed briefing records its error rather than hanging. |
| **Security** | Secrets only in server environment variables. Mobile app holds only the Supabase anon key. JWT verified on every API call. RLS on all tables. `.env` files are git-ignored. |
| **Compliance** | Neutral house rules, a dedicated compliance agent, banned-phrase checks, a fixed disclaimer and an "internal use only" label. |
| **Data provenance** | Financial figures from SEC XBRL; risk evidence quoted verbatim; link to the source 10-K. |
| **External limits** | SEC: ≤ 10 requests/second with a descriptive User-Agent. Finnhub free tier rate limits apply. |

## 13. Known Limitations

- Only SEC-registered US companies are supported.
- Some companies (e.g. JPM, PFE, CVX) put MD&A in a separate annual-report exhibit. The outlook then reads "not available".
- Companies with a new SEC registration and no 10-K yet (e.g. ExxonMobil's 2026 holding company) get briefings without 10-K text or XBRL history.
- 10-K section extraction is heuristic (heading matching on HTML-to-text) and may miss unusual layouts.
- Sections over the character caps are truncated, and the agent is told.
- Briefings poll for status; there are no push notifications or realtime updates.
- The Finnhub free tier limits request volume.
- Advisor-specific views such as watchlists or a compliance dashboard are not built.

## 15. Acceptance Criteria (v1)

1. A new user can sign up, sign in and sign out in the app.
2. Entering `AAPL` produces a `complete` briefing in under 2 minutes, with every section in §2.2 populated.
3. Financial figures in the app match SEC company-facts data for the same years.
4. Each risk shows an evidence quote that appears in the 10-K text.
5. An invalid ticker (e.g. `ZZZZZ`) produces a `failed` briefing with a readable error.
6. Each briefing has an evaluation row with four scores, a rationale and checks, plus 7 `agent_logs` rows.
7. User A cannot read user B's briefings through the API or directly through Supabase.
8. `npm run eval` completes for the golden set and writes a results file.
9. No briefing text matches the banned-phrase patterns.

## 16. v1.1 Additions: Embeddings, Memory, Guardrails, Extended Evaluation

Schema: `supabase/002_memory_guardrails_embeddings.sql` (run after `schema.sql`).

### 16.1 Embeddings and retrieval
- **Indexing:** during each briefing, in parallel with the analysts, 10-K Items 1, 1A and 7 are chunked (~1,500 chars, sentence-boundary overlap) and embedded with Voyage AI `voyage-4` (1024 dims, `input_type: document`). They're stored in `filing_chunks` (pgvector, HNSW cosine index, unique `(source_url, section, chunk_index)`).
- **Caching:** each filing is indexed once and shared across users. Older briefings are indexed on demand on the first question.
- **Search:** the `match_filing_chunks(query_embedding, filing_url, match_count)` SQL function, with `input_type: query`. Without `VOYAGE_API_KEY`, search falls back to TF-IDF keyword scoring.

### 16.2 Memory
| Kind | Storage | Used by |
|---|---|---|
| Advisor memory (`preference`, `note`, `client_context`; optional ticker; ≤ 500 chars; ≤ 50 per user) | `advisor_memories` | Briefing Writer (emphasis only, fenced as data) |
| Research memory (previous completed briefing on the same ticker) | `briefings` | Briefing Writer → new field `changes_since_last[]` |
| Conversation memory (last 12 turns) | `chat_messages` | Filing Q&A (follow-up resolution, retrieval query expansion) |

### 16.3 Guardrails
| Stage | Rule | Action |
|---|---|---|
| Input | Rate limit (briefings and questions per user per hour) | 429 |
| Input | Prompt injection (pattern set) | 400, logged |
| Input | PII: SSN, Luhn-valid card numbers, account numbers, emails, phones | Redacted before storage or LLM use |
| Input | Advice or prediction request | Neutral answer; agent declines the opinion |
| Retrieval | Passages fenced as data; instruction-like passages flagged | Logged |
| Output | Sentences still matching banned patterns after the Compliance Reviewer | Removed (evidence quotes exempt) |
| Output | PII in generated answers | Flagged |

All actions are recorded in `guardrail_events (stage, rule, action, detail)`.

### 16.4 Extended evaluation
- **Evidence match:** risk evidence quotes found in the 10-K (exact or ≥ 70% 5-gram overlap).
- **Numeric grounding:** narrative numbers matched to XBRL values, quote values, derived growth rates and margins, or numbers in the 10-K text (2% / 0.6 pt tolerance).
- Both feed `deterministicChecks` (`evidence_verified`, `numbers_grounded` at ≥ 0.8) and `evaluations.grounding`.
- **Q&A:** citation validity plus an LLM judge (faithfulness, relevance, compliance), saved on each answer's `chat_messages.evaluation`.
- **`GET /evals/summary`:** averages for briefings and Q&A, grounding rates, guardrail counts by rule and stage, and judge-vs-advisor feedback agreement.

### 16.5 New endpoints
`POST /briefings/:id/ask`, `GET /briefings/:id/chat`, `GET|POST /memory`, `DELETE /memory/:id`, `GET /evals/summary`.

### 16.6 New configuration
`VOYAGE_API_KEY` (optional), `EMBEDDING_MODEL` (default `voyage-4`), `BRIEFINGS_PER_HOUR` (20), `QUESTIONS_PER_HOUR` (60).

## 17. v1.2 Trading Features (Consumer App)

Schema: `supabase/003_trading_features.sql` (run after 002). The app has four tabs: Research, Screener, Portfolio, Alerts. It runs on iOS, Android (EAS builds) and the web.

### 17.1 Technical analysis

## 18. v1.3 Options, Backtesting and Markets

Schema: `supabase/004_options_markets.sql` adds `kv_cache`, a shared cache for options overviews and market snapshots.

### 18.1 Options math (`lib/optionsMath.js`)
- **Pricing:** Black-Scholes-Merton with greeks (theta per day; vega and rho per 1 percentage point), checked against textbook values (S=K=100, T=1, σ=20%, r=5%: call 10.4506, put 5.5735, call delta 0.6368).
- **Volatility:** implied volatility by bisection, and annualized close-to-close historical volatility.
- **Probabilities:** lognormal probability of finishing above a level, and the expected move (S·σ·√T).
- **Strategy analysis:** payoff at expiration and today, breakevens (sign change plus bisection), max profit and loss with unbounded detection, probability of profit (lognormal integration), net premium and position greeks.

### 18.2 Options data (`lib/options.js`)
- **Free plan:**
  - Inputs: the contract list (strikes and expirations within 75 days), the live underlying quote, and the previous close of the ATM call and put.
  - ATM implied volatility is solved from those prices, and every strike is modeled at that volatility. The response is labeled `data_source: "model"`.
- **Paid plan:** the chain snapshot (`data_source: "market"`), with put/call volume and open-interest ratios and max pain.
- **Default expiration:** the first one at least 5 days out.
- **Other outputs:** the probability of finishing above the technical support/resistance levels and ±1 expected move.
- **Caching:** 6 hours per ticker and expiration.
- **Options Analyst agent:** gives an IV regime, volatility and expected-move readings, a strategy explanation, key risks and a tip. It is told about earnings before expiration and never recommends trades.

### 18.3 Backtester (`lib/backtest.js`)
- **Rules:** long-only. Signals are computed at the close and filled at the next open; costs default to 5 bps per side.
- **Strategies:** `sma_cross`, `rsi_reversion`, `macd_cross`, `breakout`, `trend_filter`, each with editable parameters.
- **Output:** stats for the strategy and buy-and-hold (total return, CAGR, max drawdown, Sharpe, volatility, exposure, trades, win rate, average trade), equity and drawdown curves downsampled to about 250 points, and the last 50 trades.

### 18.4 Markets (`lib/market.js`)
- **Data:** two grouped-daily calls (latest two published sessions; a 403 on the current day falls back to the previous one), cached 3 hours.
- **Output:**
  - Index and sector ETF changes
  - Breadth across stocks priced $1+ with 100k+ volume
  - Gainers, losers and most active among liquid names ($5+, $20M+ traded)
  - A heatmap of the screener universe by sector, sized by market cap
- **Compare:** up to 5 tickers rebased to 0% on common dates.

### 18.5 New endpoints
- **Options:** `GET /options/strategies`, `GET /stocks/:ticker/options[?expiration=&explain=1]` (AI read in `ai`), `POST /stocks/:ticker/options/strategy {strategy, expiration?, explain?}` (payoff math in `analysis`, AI read in `ai`)
- **Backtesting:** `GET /backtest/strategies`, `POST /stocks/:ticker/backtest {strategy, params?, cost_bps?}`
- **Markets:** `GET /market/overview`, `GET /market/compare?tickers=A,B&days=N`

### 18.6 App
- **Markets tab:** indices, breadth, sectors, heatmap, movers and the compare chart.
- **Stock screen:** new **Options** and **Backtest** buttons.
- **New charts:** `PayoffChart` (P/L shading, breakevens, expected-move band, touch readout), `LineChart` (multi-series, fill, zero line, touch) and `Heatmap`.

### 18.7 New configuration
`RISK_FREE_RATE` (default 0.04).

## 19. v1.4 Agentic SaaS Layer

**Goal:** move from a set of research tools to an agentic product people pay for. It targets the problems retail traders raise most:
- No plan for position size and risk
- Repeating the same emotional mistakes
- Not knowing whether they beat the index
- Getting caught in dilution or pump-and-dump stocks
- Too many screens to check

### 19.1 AI Copilot (`lib/copilot.js`)
- **Loop.** A manual tool-use loop on Claude Sonnet 5.5 (effort medium, server-side fallbacks).
  - Max 8 steps per turn. Tool calls in one step run in parallel, and all results go back in one message.
  - Results are truncated to 14k characters.
  - History is the last 12 messages of the conversation.
- **Tools (18).**
  - Research tools: snapshot/technicals, earnings and insiders, red flags, 10-K search, options overview, strategy analysis, backtest, screener, market overview, performance compare.
  - User-data tools: portfolio, benchmark, journal stats, position size, list alerts.
  - Write tools: `create_alert`, `add_holding` and `log_trade`.
- **Human in the loop.** Write tools insert a `copilot_actions` row with status `pending`. The app shows a Confirm/Cancel card, and only `POST /copilot/actions/:id/confirm` executes the change. Confirming twice returns 409.
- **Safety.**
  - The input guardrail runs before the loop and the output guardrail after it.
  - The system prompt treats tool results as data, never instructions.
  - It gives educational framing only, with no buy/sell calls.
- **Trace.** Each assistant message stores `trace` (tool, input, ok, ms) and `actions`. When a conversation is reopened, each action shows its current status.

### 19.2 Trade journal (`lib/journal.js`)
- **Trade fields:** ticker, side, instrument (stock/option ×100/etf/crypto/future), qty, entry/exit price and date, stop, target, setup, emotion (8 values), notes, fees.
- **Per-trade result:** P/L, return %, R multiple (when a stop is set), hold days.
- **Stats:**
  - Totals: win rate, profit factor, expectancy, avg win/loss, avg R, % of trades with a stop, max drawdown, best/worst trade, streaks, hold days for wins vs losses.
  - Realized P/L year to date.
  - The after-loss cohort: trades opened within 2 days of a losing exit.
  - Breakdowns by setup, emotion, ticker, side and weekday.
  - Equity curve.
- **Wash sales:** a losing exit, followed by a buy of the same ticker within 30 days before or after it, where that lot is still held after the sale.
- **Coach agent:** structured output with a headline, strengths, leaks (pattern, evidence, impact), rules to consider and a next focus. Needs 3 or more closed trades and counts against the `ai_tool` quota.
- **CSV import:** matches columns by name, preferring exact header matches. It also reads stop, target, emotion, notes and instrument.

### 19.3 Risk tools (`lib/risk.js`)
- **Position size.**
  - Shares = floor((account × risk%) ÷ |entry − stop|), capped by the max position %.
  - The stop comes from the user, else 2× ATR(14).
  - The result also includes R targets and chart-based stop suggestions (2× ATR, just below support or above resistance).
- **Benchmark.**
  - Current holdings at constant share counts vs SPY, over the dates where every priced holding and SPY have data.
  - Reports total return, annualized volatility, max drawdown, Sharpe, beta and correlation.

### 19.4 Red-flag radar (`lib/redflags.js`)
- **Checks:** price < $1, penny stock (< $5), micro-cap, ATR% ≥ 8, share count growth over a year (≥ 10% medium, ≥ 25% high), recent S-1/S-3/424B filings, 8-K items 3.01 (delisting), 4.01 (auditor change), 4.02 (non-reliance) and 5.03, NT 10-K/10-Q, cash runway, going-concern language in the 10-K, and no SEC registration.
- **Output:** `risk_level` (none, low, elevated, high) with evidence per flag. Cached for 12 hours.

## 21. v1.6 Trading, Earnings, Email and Production Hardening

### 21.1 Paper trading (`lib/paper.js`)
- **Account.** `paper_accounts` holds cash, starting cash, realized P/L and the number of resets. Positions (`paper_positions`) store quantity, weighted average cost and when they were opened. Orders (`paper_orders`) are market, limit or stop; good for the day or until cancelled; and open, filled, cancelled, rejected or expired.
- **Fills.**
  - `shouldFill`: market orders fill at the last price while NYSE is open (9:30 to 16:00 America/New_York, holidays not modeled). Buy limits fill at or below the limit, sell limits at or above it. Stops trigger when the price crosses them.
  - `applyFill`: updates the weighted average cost; sells realize P/L and can't exceed the shares held.
  - Cash is re-checked at fill time, so an order that no longer fits is rejected.
- **Buying power.** Cash minus what open buy orders reserve. A preview returns the estimated cost, buying power after, blocking problems, warnings (such as "fills at the next open"), and the user's rules checklist.
- **Processing.** On every account read, and by the `paper` job during market hours. Day orders expire after the close, and limit or stop fills send a notification.
- **Journal.** Each sell fill becomes a closed journal trade (setup `paper`, `external_id = paper:<order id>`).
- **Copilot.** `get_paper_account` (read) and `propose_paper_order` (a proposal the user must confirm). The Copilot has no real-money tools.

### 21.2 Real trading through the user's broker (`lib/broker.js`)
- **Switch.** Requires `BROKER_TRADING_ENABLED=true` and SnapTrade keys. Connections are requested as `trade` instead of `read`.
- **Preview.** Resolves the symbol with `referenceData.symbolSearchUserAccount`, then calls `trading.getOrderImpact`. The result is stored as a `live_orders` row with status `previewed`, the SnapTrade trade id, price, commission and cash after.
- **Place.** `trading.placeOrder({ tradeId })` runs only with `confirm: true`, within 4 minutes of the preview, and only once. Broker errors are stored and shown.
- **App.** The user must tick a real-money acknowledgement before the Place button enables.

### 21.3 Earnings companion (`lib/earnings.js`)
- **Implied move.** Taken from the options overview at the first expiration on or after the reaction day (the day after for after-close reports).
- **Historical moves.** Computed by `historicalMoves` over the last 8 reports: before-open reports are measured from the prior close to the report-day close, after-close reports from the report-day close to the next close.
- **AI preview.** Agent `earnings_companion` (effort low) writes the headline, what to watch, the setup and a risk note. Cached for 6 hours and counts against the `ai_tool` quota.
- **Jobs.** On report days the `earnings` job (11:00 to 14:00 UTC) notifies holders and watchers with the implied move against the average past move. The recap refreshes the events summary.

### 21.4 Weekly email (`lib/email.js`)
- **Content.** Portfolio return vs SPY (5 sessions), closed trades this week, the paper account, earnings in the next 7 days and thesis checks. The HTML is email-safe and escapes all user content.
- **Sending.** Resend API (`RESEND_API_KEY`, `EMAIL_FROM`), Sundays from 14:00 UTC, once per week (`last_weekly_email`). Users opt out with `weekly_email`.
- **Unsubscribe.** An HMAC token (`/email/unsubscribe?u=&t=`, GET and POST for RFC 8058), plus the `List-Unsubscribe` header.

### 21.5 Billing additions
- **Annual plan.** `interval: year` uses `STRIPE_PRICE_PRO_ANNUAL`. Subscriptions store `interval` and `paused_until`, and a paused subscription doesn't grant Pro.
- **Cancel flow.**
  - Reasons map to offers: taking a break or not using it → pause billing for 30 days; too expensive → `STRIPE_RETENTION_COUPON` if set, else switching to yearly.
  - Cancelling sets `cancel_at_period_end`, and resume clears it.
  - Every step is stored in `cancel_feedback` and sent to analytics.

### 21.6 Hardening
- **Rate limits.** In-memory fixed one-minute windows per IP: `RATE_LIMIT_PER_MIN` (240) for reads and `RATE_LIMIT_WRITES_PER_MIN` (60) for writes. Exceeding them returns 429 with `Retry-After`. `trust proxy` is set for Render and Vercel.
- **Monitoring.** `@sentry/node` when `SENTRY_DSN` is set. Every route helper and the final Express error handler report 5xx errors, failed jobs and AI provider auth or billing failures. Request bodies, cookies and auth headers are removed before sending.
- **AI errors.** `friendlyAiError` maps Anthropic API errors to a 503 with a safe message.
- **Tests and CI.** `node --test` with `test/setup.js` (local mode, offline): 18 tests covering paper fills, FIFO round trips, post-earnings moves, option P/L attribution, position size, journal stats and wash sales, CSV import, rules, schedules, the rate limiter, unsubscribe tokens and email escaping. `.github/workflows/ci.yml` runs the server check and tests and the app web build.

  - Phone: Today, Copilot, Trade, Portfolio and More. Research moved to More.
